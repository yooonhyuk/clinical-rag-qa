# 011. OUT_OF_SCOPE 분류기가 프로토콜의 영상 일정·기준 질문을 진단 요청으로 거절함 (답 있는 질문의 10.9%)

- 상태: 열림
- GitHub: https://github.com/yooonhyuk/clinical-rag-qa/issues/12
- 발견: 2026-10-09, 실제 프로토콜 코퍼스(로컬 전용, 31개 PDF) 평가
- 영향 범위: `SCOPE_CLASSIFIER=embedding`(기본값), 1단계 거절. 검색 전에 거절되므로 답변·인용이 아예 없음
- 결과 파일: `eval/results/2026-10-09_private-protocols_bge-m3-vector*-gemma4-e4b*_8487c910/` (집계만)

## 증상

답이 있는 64문항 중 7문항(10.9%)이 생성 전에 OUT_OF_SCOPE로 거절됐습니다. HNSW·exact 두 실행에서 같은 7문항이었습니다. 분류기는 결정적이라 실행마다 같습니다.

| 문항 | 유형 | 질문 내용 (직접 쓴 질문의 요지) | kNN margin (기준 0.056) |
|---|---|---|---|
| r07 | imaging_schedule (en) | 림프종 시험에서 PET와 진단 CT를 어느 방문에 찍는가 | 0.058 |
| r08 | imaging_schedule (ko) | 교모세포종 시험에서 방사선치료 후 조영증강 MRI 시작 시점과 간격 | 0.061 |
| r09 | imaging_schedule (en) | 다른 교모세포종 시험의 MRI 추적 일정 | 0.065 |
| r11 | imaging_schedule (ko) | 치료 중단 환자의 영상 검사 주기 | 0.078 |
| r30 | response_criteria (en) | 항암치료 후 어떤 환자가 방사선치료를 받는가(Deauville 기준) | 0.124 |
| r39 | eligibility_imaging (en) | 영상 수집 계획에서 뇌 MRI가 screening·추적에 필수인가 | 0.066 |
| r43 | eligibility_imaging (ko) | 등록 대상이 되는 interim PET-CT 결과 | 0.061 |

진단·치료 요청 5문항은 모두 거절했고(5/5), 같은 주제 무응답 1문항(r70)도 이 단계에서 거절됐습니다(거절 자체는 맞음).

## 원인 (관찰)

- B6 분류기는 bge-m3 kNN으로 "진단·치료 요청 예시"와 "문서 질문 예시"까지의 평균 cosine 차이를 봅니다(`rules/scope_exemplars.yaml`, margin 0.056은 예시만으로 leave-one-out 조정). 예시의 문서 질문은 업로드·QA 운영·가이드라인 조항 위주라, "MRI를 언제 찍나요", "PET 결과에 따라 어떤 치료" 같은 **임상시험 영상 운영 질문**은 진단 요청 예시("이 MRI 소견이…", "치료를 바꿔야…")에 더 가깝게 놓입니다.
- 7문항 모두 margin을 0.002~0.068 넘었습니다. 임계값을 조금 올려도 r30(0.124)은 남습니다.
- 공개 코퍼스 평가(99문항)에서는 같은 분류기가 답 있는 질문을 하나도 거절하지 않았습니다. 공개 질문은 가이드라인 조항을 묻는 문장이 많고, 이번 질문은 시험 방문·영상 modality·치료 분기를 직접 언급합니다.

## 왜 중요한가

임상시험 영상 운영자(이 시스템의 주 사용자)가 가장 자주 묻는 것이 "언제 어떤 영상을 찍는가"입니다. 그 질문을 진단 요청으로 오인하면 시스템이 가장 필요한 질문에 답하지 못합니다.

## 수정 방향 (평가셋을 보고 조정하지 않음)

- 문서 질문 예시에 "프로토콜 영상 일정·반응 기준 적용" 유형을 추가하되, **이 평가셋과 겹치지 않는 새 문장**으로 쓰고 margin은 예시 leave-one-out으로만 다시 정합니다. 새 held-out(프로토콜 운영 질문 + 진단 요청)을 따로 만들어 확인합니다.
- 정밀 정규식 1층에 "환자/제 환자/이 영상" 같은 **개별 환자 지시어**가 없으면 kNN 거절을 한 단계 약하게(부분 답변이나 경고) 처리하는 방안을 검토합니다.
- 이 평가셋의 7문항으로 margin을 맞추지 않습니다(테스트셋 튜닝 금지).
